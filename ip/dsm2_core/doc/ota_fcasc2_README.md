# ihp-sg13cmos5l Fully Differential Folded Cascode OTA, Unit-Device Version

A fully differential folded cascode OTA with a PMOS input pair for the switched-capacitor integrator of the first-order delta-sigma battery monitor (1.5 V, 1.45 to 1.55 V, `fs = 1.024 MHz`, OSR 512, -40 to 125 °C). It is sized to the system-level design point (`C1 = 64 fF`, `C2 = 384 fF`, fanout 2), with every branch current an integer multiple of the 200 nA bias input and every device built from unit devices, so the layout can be drawn as unit arrays.

`ota_fcasc2` is a sibling of [`ota_fcasc_fd`](../ota_fcasc_fd/README.md), which keeps its older sizing (tail 800 nA, `L = 5 µm` bias stacks) because its layout is drawn by hand. The port list, the symbol and the split into blocks are the same, so `ota_fcasc2_top` is a drop-in replacement and the floorplan of the old layout maps onto it block by block. The layout is generated by a script, see [Layout](#layout).

The common-mode feedback is external: `vfb` drives the NMOS sinks and `vbn` brings out the matching bias voltage, so tying `vfb` to `vbn` biases the OTA open loop, as the testbenches do. `di_ena` switches the bias off.

| Pin | Direction | Function |
| --- | --- | --- |
| `vdd`, `vss` | inout | 1.5 V supply |
| `vi_p`, `vi_n` | input | differential input |
| `voutp`, `voutn` | output | differential output |
| `vfb` | input | common-mode feedback, gate of the NMOS sinks |
| `vbn` | output | NMOS sink bias voltage, tie to `vfb` for open-loop biasing |
| `ibias_200n` | input | 200 nA bias current sunk by the OTA, about 0.61 V at the pin |
| `di_ena` | input | enable, active high, edges of at least 30 ns at this pin |

| Cell | Content |
| --- | --- |
| `ota_fcasc2_top` | Top cell: the four blocks below plus ten `cap_dec` |
| `ota_fcasc2_dp` | PMOS input pair with its dummies |
| `ota_fcasc2_pbiascasc` | PMOS tail and loads with their cascodes, the wide-swing PMOS bias, enable switches |
| `ota_fcasc2_nbiascasc` | NMOS sinks (driven by `vfb`) and folded cascodes, the NMOS bias diodes, the sink of the PMOS reference, enable switches |
| `ota_fcasc2_ena` | Enable inverters, `d_ena` and `d_ena_b` from `di_ena` |
| `cap_dec` | Thick-oxide PMOS decoupling capacitor between `vdd` and `vss` |


## Topology

- **Input pair** `MP1`/`MP2`, 600 nA each, bulk on the tail node.
- **Tail** `MP3` with the cascode `MP10`, 1.2 µA. `ota_fcasc_fd` has no tail cascode. Here it keeps the tail current at the mirror ratio: the wide-swing bias puts the reference `MP8` at a small `V_SD`, and an uncascoded tail at 0.4 V would carry 6 % more.
- **PMOS loads** `MP4`/`MP5` with the cascodes `MP6`/`MP7`, 1.0 µA each.
- **NMOS sinks** `MN1`/`MN2` (1.6 µA each, gate `vfb`) take the pair current plus the output branch, the folded cascodes `MN3`/`MN4` carry 1.0 µA each.
- **NMOS bias**: the 200 nA input flows through the pass switch `MNSW5` into the stacked diodes `MN6` over `MN5`, which give `vcn` and `vbn`. The sinks then sit at `V_DS = V_GS(MN5)`, about 0.3 V. For LV NMOS at `gm/ID = 18` that is only 0.15 V above `V_dsat` plus margin, the lowest output is then about 0.4 V, and the modulator needs 0.505 V. The diode stack is kept: it needs no resistor, starts without help, and the larger `V_DS` raises the sink output resistance, which sets the gain.
- **PMOS bias, wide swing**: `MN7`/`MN8` sink a 200 nA copy from `MP8`/`MP9`. A stacked PMOS diode would put the load sources at `V_SD = V_SG`, about 0.4 V, and cap the output at about 1.0 V, exactly the 1.0 V the modulator swings to at 1.5 V, and below it at 1.45 V or in the slow corner. So `MPR`, a long PMOS in triode (`W = 0.5 µm`, `L = 10 µm`, gate on `d_ena_b`), drops about 60 mV between `vbp` and `vcp`, and the sources sit at about 0.1 V. `MPR` is off when disabled, so it is also the enable switch of that branch.
- **Enable**: `MNSW1`/`MNSW3`/`MNSW4` pull `vfb`, `vcn` and `vbn` to `vss`, `MPSW3`/`MPSW4` pull `vbp` and `vcp` to `vdd`, `MNSW5` and `MPR` open the two reference branches.
- **`di_ena` edges**: `di_ena` needs edges of at least 30 ns at the OTA pin. In the whole-OTA start-up bench (30 runs, sim) 3 ns edges take `MPEN0`, `MNEN0` and `MNEN1` to Vds 1.62 V and 1 ns edges to 1.69 V, with the gate oxide of several devices over 1.65 V. 10 ns edges stay below the 1.6 V Vds limit, 30 ns leaves a margin.
- **`MNC7` on `vd7`**: one NMOS unit (0.5/3) with its gate on `vd7` and source, drain and bulk on `vss`. While the OTA is off, `vcp` sits at `vdd` and `MN7`, `MN8` are off, so `vd7` floats and the enable edges kick it below `vss`. Without the cap `MN8` reached Vds 1.66 V in 14 of 30 start-up runs, over the 1.6 V limit (sim). With it the peak is 1.553 V and no LV device of the OTA exceeds 1.6 V Vds or 1.65 V gate oxide in the same 30 runs (peaks 1.593 V Vds on `MNEN1`, 1.615 V gate-drain on `MN8`, sim). In the layout it is a unit of R2, next to MN7.
- **Folding headroom**: `I_fold/I_tail` = 1.6/1.2 = 1.33, above the 1.2 guideline. The system-level design point sizes the output branch at `Id1`, which gives 1.0.


## Sizing

`scripts/sizing/size_ota_fcasc2.py` derives the system-level design point (settling budget, input pair, cascode stack, bias, power) from the 1 mV LSB on 1.5 V, OSR 512 and `H_inf` 1.2 loop with pygmid and the CMOS5L tables in `../ota_fcasc_fd/scripts/sizing/data/`, then evaluates the unit-device point and prints every device and every branch current. It needs `pygmid`, `numpy` and `deltasigma` (package `python-deltasigma`):

```sh
python macros/ota_fcasc2/scripts/sizing/size_ota_fcasc2.py              # the design
python macros/ota_fcasc2/scripts/sizing/size_ota_fcasc2.py --point current  # the sizing before the equal-L rule
python macros/ota_fcasc2/scripts/sizing/size_ota_fcasc2.py --compare    # model table of the equal-L candidates
```

The system-level leaky-integrator sweep is not rerun, its result (50 dB integrator gain) is taken as an input.

Every NMOS has the same L and every PMOS has the same L, so the layout can place each type as one array with straight columns. The input pair and `MPR` are the two exceptions. Unit devices, all `ng = 1`:

On the PMOS side the cascode W is what matters, its L is already the source L. With every NMOS at 0.5/3, a cascode of 1/2 instead of 3.5/2 costs 1.8 dB of gain and the swing falls to 0.89 V, 2/2 costs 0.45 dB. PMOS at L = 1 µm (sources 0.5/1, cascodes 2/1) meets every limit over the 135-point sweep with the same margins as L = 2, needs no exception for the pair and would cut the PMOS gate area from 210.5 to 77.5 µm², but raises the bench noise from 923 to 1004 µVrms and the offset spread from 3.3 to 4.0 mV (40 runs), so the PMOS stay at L = 2. These noise numbers come from the earlier noise bench, whose noisy feedback resistors are in them and which is not comparable with the 416.5 µVrms of [Simulation Results](#simulation-results). The screen was not repeated. The pair at L = 2 µm (2/2) costs settling: tau worst case 29.7 ns against 30.5, swing 1.03 V, and the bench noise does not improve (945 µVrms), so the pair stays at `W = 2 µm`, `L = 1 µm`.

`MPR` works as a resistor, its L sets the drop. It is one device at `L = 10 µm`, the longest L the project allows. At 0.5/13 it dropped 82 mV and the PMOS sources sat at `V_SD` 0.121 V, at 0.5/10 it drops 62 mV and they sit at 0.105 V (sim, tt, 27 °C, 1.5 V). The gain at tt falls by 0.5 dB and every limit still holds, see [Simulation Results](#simulation-results).

Two notes on the system-level numbers:

- The system-level design evaluates `beta` at the target `wug`, before `gm_scale = 2` doubles the pair. With the `Cgg1` of the pair it actually sizes (41 fF), `beta` is 0.785, not 0.820, and `tau` is 17.7 ns rather than 15.3 ns. The settling testbench measures 0.785 and 16.2 ns.
- The OTA gain requirement is 51.7 dB, 50 dB of integrator gain over `beta` = 0.820, as the code computes. The system-level specification table says 53.3 dB with `beta` = 0.69, a leftover of the old capacitors. With the real `beta` of 0.785 the requirement would be 52.1 dB.

Against the earlier dummy counts on the same image, tau moves from 16.23 to 16.29 ns, the cascode starvation from 18 to 19 ns and the power from 5.42 to 5.40 µW. It is flicker dominated and splits evenly over the pair (21.0 µVrms each), the NMOS sinks (20.3) and the PMOS loads (20.3), every other device is below 1 µVrms. The integrator refers it to its input with 1/2, which gives 25.2 µVrms. The `sc_int2` pnoise read 26.6 µVrms for the OTA with the earlier 0.5/13 `MPR`, it was not rerun. ## Layout

`layout/ota_fcasc2_top.gds` is written by the generator `layout/ota_fcasc2_gen.py` (KLayout Python, live `SG13_dev` PCells, helpers in `macros/scripts/lay_helpers.py`). Regenerate it with `make layout`, never edit the GDS by hand. `PLACE_ONLY=1` writes the placement without routing. The blocks are cells `ota_fcasc2_<block>_blk` inside the top. Their names differ from the schematic subcircuits on purpose, so LVS compares the macro flat.

The macro is 63.83 x 24.44 µm (1560 µm²). Before the dummy rows and row-end dummies of 2026-10-19 it was 63.83 x 18.505 µm (1181 µm²), the first generated layout 59.44 x 52.13 µm (3099 µm²), and `ota_fcasc_fd` is 47.785 x 110.5 µm (5280 µm²).

One vertical axis runs through the middle of the macro. Every block is a 2D array of one unit size, the right half the mirror image of the left (the nets may differ), and the build fails unless Activ, GatPoly, Cont, pSD, NWell and Metal1 XOR to zero against their mirror image. Seven allow-listed Metal1 boxes differ: the vp8 straight column of MP8/MP9 and the vdd straight column of MPSW3/MPSW4, whose mirror partners join two nets, the MPSW3 drain drop, and the R2 axis dummy's column up to R1, whose image is the vfb drain of MNSW1.

Every array has a dummy at both ends of each row and a dummy row above and below, full units where the devices are matched. A dummy row is one strip: its Activ (and pSD) runs on across the breaks of the row it copies, since all its columns carry one net.

- Every NMOS is one 0.5/3 unit. R1 and R2 run across the axis, R3 to R5 are split into two wings around the input pair, which keeps the pair's window only as tall as the pair. Over the pair only R2's axis dummies and MNSW1 face it.
- Input pair: `D A A B B | B B A A D` with A = MP1, B = MP2 and the MPD1 dummies on both ends, 2 µm fingers.
- MN1/MN2: the right wing is the pure mirror image of the left, so both devices have their centroid on the axis and in the middle of R3/R4, and every drain column runs straight through both rows. MND1 ends each core row, and the core rows are continuous strips.
- MN3 (left) and MN4 (right) are mirror images in R1, sources toward the axis. MP4/MP5 and MP6/MP7 run in the groups `4 | 55 | 44 || 55 | 44 | 5`.
- R2 shares diffusion where the nets allow it on both sides: left vcn (MN6/MNSW3), vss, vbn, right vd7 (MN8/MN7), vss, and vss on the axis.
- Gates: R3/R4 share one strap in their gap, R1 and R0 share one vcn strap, R2 has a strap per unit under the row, R5 one strap per wing under the row, P1 a deep strap under the row, P2 a strap over it, P3 a strap over it, P0 a strap under it.
- Routing runs over the arrays, there is no routing channel. Metal1 for the device columns, their straight extensions, pads and the supply bars (all mirror symmetric, a pad without a via on one side is the image of a real landing on the other). Metal2 tracks over the rows (vfb, vbn, vcn, the vout tracks over R0 and over P2, d_ena_b and d_ena over the psub band). Metal3 verticals. Metal4 for the vd1/vd2 buses, the vd7 link from MNC7 to the MN7/MN8 column, and the pins. Every via landing has two cuts.
- vd1 and vd2: an upper Metal4 bus on the cascode sources (vd1 left, vd2 right), one Metal3 drop each over R2's axis dummies, and two lower Metal4 buses across the core and the pair. The lower buses swap levels at the axis (vd1 on Metal4 at x = 0, vd2 on Metal3), because one level runs over R4 and the other over the R3/R4 gap, and straight buses gave the net over R4 0.94 fF more to vss in both Magic and kpex.
- A third net that passes one output passes the other the same way: the vcp riser from MN8 and its jog have a vcn image on the left, the MNSW3 and MNSW5 gate risers have vcn images from the MN8 and MN6 gates, the MNSW4 gate riser has the MNC7 gate (vd7) as its image, the d_ena_b track spans both vout tracks, and d_ena has a dead mirror image over voutp. Pair balance in the build, metal area per node and layer: voutp/voutn and vi_p/vi_n within 3 %, vd1/vd2 within 5 % summed over the layers.
- Supplies: one nwell ring on vdd around the PMOS area and one psub ring on vss at the macro edge. They carry no `well`/`sub!` text and no supply runs along them. vss arrives on two Metal3 trunks that land on the vss bar under R5, which stops at the pair window so that vi_n, whose strap sits just over it, sees no more vss than vi_p. vdd arrives on the vdd bar over P0, and P1's vdd columns run through P0. Each ring is only tied to its bar. The dummy strips R0 and P3 have their own 0.16 µm bars, R0 on vss through R1's dummy columns, P3 on vdd through P2's outer dummy columns.
- Pins are on Metal4, vbn on Metal3 in the left side strip (the image of ibias_200n on the right). vss has a Metal4 port on each trunk. One NoMetFiller rectangle covers the whole macro, prBoundary (189/0) marks it.

## Testbenches and CACE

The Makefile, the testbench mechanics and the CACE flow are those of `ota_fcasc_fd`, see its [README](../ota_fcasc_fd/README.md) for every target. What differs:

- `make sim-cace CACE_JOBS=3` limits CACE to three parallel simulations (empty uses every core).
- `sim-cace` runs CACE with `--nofail`, so the noise set, which fails by design, does not stop the chain before the transient sets. The summaries still mark it as failing.
- The settling testbench and its CACE templates also run an operating point (supply power) and a closed-loop dc sweep (output swing) before the transient. The swing is the differential output range over which the incremental gain `d(vod)/d(vvg)` stays above 51.73 dB. Its limit is 0.98 V, twice the 0.491 V peak integrator state of the ideal modulator at -0.5 dBFS. The system-level `vod_swing_design` (1.84 V) is a saturation estimate with `V_dsat + 50 mV` on every device, not a gain criterion, and is quoted in the datasheet description only.
- The CACE limits follow the system-level design point: `dcgain` ≥ 51.73 dB, `tau` ≤ 30.5 ns, `err_d` ≤ 0.32 % (the static error `1/(1+beta·A0)` at the gain limit), power ≤ 10 µW. The IRN limit stays at 290 µVrms, the continuous-time map of the closed-loop bench number, so the gap to it keeps showing. `vn_d` has no limit until the integrator budget is final.
- The noise testbench and its CACE templates run three `noise` analyses: the closed-loop bench (`irn`), a wide-band one for the plot, and an open-loop one with C1 altered to 1 F (`vn_d`). xschem's `res.sym` does not write `noisy=` to the netlist, `res_noisy.sym` does. The bench writes a Spectre-style device noise summary per band run with `macros/scripts/noise_summary.py`, which needs the last argument of `noise` (`pts_per_summary`) set to 1 so that ngspice keeps the per-source contributions.
- The settling and `bias_gm` benches subtract the virtual ground before the step, the input offset, from the gain measure, as the CACE templates do, and print it as `vos_uV`. The I_fold/I_tail and cascode starvation lines read device currents by their schematic path, so with the PEX DUT they are skipped with a message.
- Conditions: `ss`/`sf`/`tt`/`fs`/`ff`, 1.45/1.5/1.55 V, -40/27/125 °C.
- `Acl` and `beta` are read from the capacitors in the benches, not typed in. The enable input of every bench and template and the supply of the ac bench follow `vdd`.
